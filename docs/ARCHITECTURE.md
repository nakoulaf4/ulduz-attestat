# Ulduz — Архитектура приложения (`docs/ARCHITECTURE.md`)

**Ulduz** — полностью статическое веб-приложение без шага сборки (HTML5 + CSS3 + нативные ES-модули), предназначенное для локального или статического хостинга (`python -m http.server` из директории `site/`).

---

## 2. Ключевые архитектурные решения

### 2.1. Контракт и изоляция предметных модулей
- Авторы предметов реализуют только `site/js/subjects/<id>/index.js` и `site/data/original/<id>.json`.
- Реестр `site/js/subjects/index.js` динамически импортирует все четыре модуля через `Promise.all`. Если модуль предмета ещё не готов или содержит ошибку экспорта, он автоматически подменяется безопасной заглушкой из `site/js/app/demo-tasks.js`, не ломая остальные предметы.
- `site/js/core/rng.js` гарантирует воспроизводимость: по паре `(typeId, seed)` генератор строит идентичное задание.
- `site/js/core/contract.js` объединяет схему валидации (`validateTask`) и нормализацию/проверку ответов (`checkAnswer`, `normalizeText`, `parseNumber`), единую для фронтенда и скрипта контент-верификации `tools/selftest.mjs`.

### 2.2. Отрисовка формул, текстов и графики
- Вся математика рендерится локально через `vendor/katex` (`$...$` и `$$...$$`). Вне математических разделителей `___` автоматически превращаются в визуальные пропуски `<span class="gap"></span>`.
- Поддерживаются два режима изображений в `TaskImage`: inline-SVG (`image.svg`, наследует `currentColor` темы) и внешние файлы (`image.src` относительно `site/`).
- Для заданий с `passage` на широких экранах (≥ 1040px) включается двухколоночный split-view с фиксированным прокручиваемым текстом слева и кнопками изменения размера шрифта (`A−` / `A+`), а на мобильных устройствах — переключатель «Текст + Вопрос / Текст / Задание».

### 2.3. Оценивание экзамена ДИМ (`site/js/core/scoring.js`)
- `evaluateExam(tasks, responses, subject)` проверяет каждое задание через `checkAnswer`, группирует результаты по темам (`topicBreakdown`, отсортировано по возрастанию процента выполнения) и вычисляет итоговый 100-балльный результат ДИМ:
  - Если модуль предмета предоставляет собственную функцию `subject.score(tasks, earnedList)`, используется именно она (флаг `hasCustomScore` корректно обрабатывает даже нулевой результат).
  - Иначе применяется пропорциональный перевод первичных баллов на 100-балльную шкалу без штрафов за ошибки.
- В комплексном режиме `#/exam/all` задания группируются по предметам, для каждого рассчитывается собственная 100-балльная шкала, после чего баллы суммируются (например, до 300 баллов для стандартной тройки «Аттестат»).

### 2.4. Локальное состояние и устойчивость к перезагрузке (`site/js/core/storage.js`)
- Всё состояние хранится под ключом `ulduz_state_v1` в `localStorage`:
  - `stats`: счётчики по предметам, темам и типам заданий;
  - `mistakes`: автоматически пополняемый банк ошибок (`resolved: false` → `true` после верного повторного решения);
  - `bookmarks`: закладки пользователя;
  - `solvedOriginals`: прогресс по оригинальным задачам PDF;
  - `exams`: история завершённых симуляций (до 50 записей);
  - `activeExam` и `activePractice`: черновики текущих сессий (при обновлении страницы F5 экзамен продолжается с сохранёнными ответами, флажками и оставшимся временем).

### 2.5. Маршрутизация (Hash Router)
- `#/` — Главная страница (`home.js`)
- `#/subject/:id` — Хаб предмета (`subject.js`)
- `#/practice/:id?topic=...&type=...&diff=...&seed=...` — Практика (`practice.js`)
- `#/exam/:id?source=generated|0903|1503&resume=1` — Экзамен (`exam.js`, в т.ч. `:id = all`)
- `#/originals/:id?pdf=0903|1503&n=1` — Оригиналы PDF (`originals.js`)
- `#/mistakes?tab=mistakes|bookmarks&subject=...` — Ошибки и закладки (`mistakes.js`)
- `#/stats` — Статистика и экспорт/импорт прогресса (`stats.js`)
